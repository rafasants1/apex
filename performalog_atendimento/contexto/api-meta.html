Integração com a API da Meta (WhatsApp Cloud API)

Tudo o que o backend do Performalog precisa para conversar com a Meta: configuração da conta, chamadas, webhooks, identidade do contato, a tela de conversas, os modelos (templates), o motor de disparo em massa, erros, preço e as tabelas do banco. As regras marcadas META foram conferidas na documentação oficial em 08/10/2026. O que é escolha nossa aparece como PROTÓTIPO e CONFIRMAR; o que depende da Performa fica como PERGUNTA.

Premissa desta página: o sistema fala direto com a Cloud API (graph.facebook.com), sem parceiro. A decisão ainda está aberta (Q-CF2). Se a Performa preferir um parceiro, muda só a camada MetaClient (endereço e autenticação); payloads, webhooks e regras continuam os mesmos, porque os parceiros repassam a Cloud API.

Arquitetura

A Meta nunca chama o bot nem a tela. Toda mensagem do cliente chega como webhook, e toda resposta sai como uma requisição nossa para a API. A tela de conversas mostra só o que o nosso banco guardou.

  1. Recebedor de webhook · rota HTTPS pública do Performalog. Confere a assinatura, grava o corpo bruto em wa_webhook_event, responde 200 e enfileira. Nada de regra de negócio aqui.
  2. Fila e processadores · um processador para mensagens recebidas (contato, conversa, bot, distribuição), um para status (ticks, custo, falhas, campanha) e um para eventos de conta e modelos.
  3. Fila de saída por número · todo envio (atendente, bot, régua de cobrança, campanha) passa por ela, com prioridade e controle de vazão. Só ela chama POST /messages.
  4. MetaClient · única camada que conhece URL, versão, token e formato de erro da Graph API.
  5. Serviço de mídia · baixa a mídia recebida em até 5 min, guarda no armazenamento do Performalog e sobe arquivos para envio.
  6. Tempo real · depois de gravar, o servidor avisa as telas abertas (WebSocket ou SSE). A tela não consulta a Meta.
  7. Eventos para o Performalog · mensagem recebida, protocolo, status etc. continuam alimentando a Jornada do cliente, que hoje recebe os webhooks da Maxbot (CF-42).

Referência: validar a assinatura do webhook · codigo-referencia/webhook-assinatura.js
// Validação da assinatura do webhook da Meta (AP-21).
// Exemplo em Node.js; adaptar à linguagem do backend do Performalog (Q-AP4).
// corpoBruto: Buffer com o corpo exatamente como chegou, antes de JSON.parse.
const crypto = require("crypto");

function assinaturaValida(corpoBruto, cabecalho, appSecret) {
  const esperado = "sha256=" + crypto.createHmac("sha256", appSecret).update(corpoBruto).digest("hex");
  const a = Buffer.from(esperado), b = Buffer.from(cabecalho || "");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

module.exports = { assinaturaValida };

  1. Conta · responder Q-AP1, criar app e usuário do sistema, testar com o número de teste da Meta (AP-01 a AP-12).
  2. Webhook · verificação, assinatura, tabela de eventos, fila, descarte de repetidos (AP-20 a AP-25).

  5. Modelos · criar, sincronizar, webhooks de situação e qualidade (AP-60 a AP-66).
